## 감사 질문

1. 승인된 새 기획이 핵심 재미를 강화하는가.
2. 기존 정본·구현·PR·Sheet와 충돌하는가.
3. 새 규칙 사이에 지배 전략·설명 불가능성·랭킹 불공정이 있는가.
4. 구형 문서가 이후 작업에서 잘못 참조될 가능성이 있는가.
5. 구현에 넘기기 전에 추가 Definition of Ready가 필요한가.

## 결론

판정: `KEEP_AND_REBASE`

새 기획은 기존 LIFO 정체성을 유지하면서 선로 건설·비용·제한 시간·Combo를 결합해 핵심 재미를 더 직접적으로 만든다. 다만 기존 제품 기준선은 무한 생존·연료·BOOST 중심이므로 현재 구현 계획 위에 추가할 수 없다. 제품 기준선과 실행 로드맵을 교체하고 새 DoR을 작성한 뒤 구현해야 한다.

## 핵심 재미 적합성

### 강화된 인과

```text
선로 선택
→ 화물 조우 순서
→ LIFO 스택
→ 역 방문 순서
→ Combo
→ 시간·비용·점수 결과
```

각 판단이 다음 판단의 입력이 된다. 이는 메타·반사신경보다 퍼즐 계획을 전면에 둔다.

### 유지할 보호 규칙

- 마지막 적재 화물이 다음 하역 대상이다.
- 같은 종류가 TOP에서 연속될 때만 그룹 하역한다.
- 화물·역은 색상과 모양을 함께 사용한다.
- 빠른 탭보다 순서·노선 판단이 성공 원인이어야 한다.
- 꾸미기는 성능에 영향을 주지 않는다.

## 충돌 Findings

### F115 · P0 · 제품 목적 충돌

기존 `SX-DEC-002`는 무한 생존과 최고 점수 경쟁을 제품 목표로 한다. 새 기준선은 유한 스테이지 배송 퍼즐이다.

조치: `SX-DEC-027`이 대체. 기존 결정은 `[대체됨]` 역사로 보존.

### F116 · P0 · 선로 권위 충돌

기존 맵은 생성 시 완성된 15×10 connected RailGraph를 권위로 삼는다. 새 기준선은 플레이어가 선로를 건설한다.

조치: 지형·역·화물·건설 가능 영역을 `MapDefinition`, 플레이어 선로를 별도 `TrackLayout`로 분리하는 새 설계 필요. 기존 graph signature를 플레이어 해답 identity로 재사용 금지.

### F117 · P0 · 종료·난이도 충돌

기존 연료 0 종료와 시간 경과 pressure는 새 제한 시간 실패 규칙과 양립하지 않는다.

조치: fuel·DifficultyDirector 제품 규칙 `[폐기]`; 구현은 `LEGACY_IMPLEMENTATION`으로 격리.

### F118 · P0 · 적재 규칙 충돌

기존 capacity 8·화물 감속·respawn은 무제한 적재·고정 화물 배치와 충돌한다.

조치: capacity 8·감속·respawn 제품 규칙 `[대체됨/폐기]`. compact token 표현은 무제한 목록 전체를 물리 화차로 펼치지 않는 방향으로 재설계.

### F119 · P0 · 온보딩 충돌

기존 실제 첫 endless run 상황형 온보딩은 1~10 수작업 튜토리얼과 충돌한다.

조치: 기존 온보딩 spec `[대체됨]`; 실패 분석·요청형 단계 힌트는 재사용 가능.

### F120 · P1 · 분기 상태 충돌

기존 분기는 통과 후 기본 상태로 복귀한다. 새 결정은 다시 조작할 때까지 유지한다.

조치: 새 제품 권위로 교체. 기존 테스트는 역사적 동작 증거일 뿐 새 수용 기준이 아님.

### F121 · P1 · PR/로드맵 권위 충돌

기존 VS03-R1→VS03-05A 실행 순서는 old core를 전제로 한다.

조치: 기존 package plan `[대체됨]`. 다음 권위는 `FINITE_PUZZLE_DOR`이며 코드 구현 자동 진행 금지.

## 적대적 설계 검토

### F122 · 무제한 적재 가독성

위험: 화물 수가 많을 때 실제 화차를 모두 길게 표시하면 맵과 분기를 가린다.

보완:

- domain stack은 무제한
- 월드 표현은 기관차 뒤의 최근/TOP 화물과 압축 수량 표시
- 전체 순서는 별도 스택 패널에서 스크롤·압축 표시
- TOP과 다음 연속 그룹을 가장 크게 강조

검증 Gate: 8/16/32개 적재에서 TOP·연속 그룹·맵 가독성 human test.

### F123 · 저비용 선로 지배 전략

위험: 가격 순위가 모든 구간 저비용 선로로 고정될 수 있다.

보완:

- 제한 시간이 실제 반대 압력으로 작동해야 함
- 맵별 최소 시간 여유를 조정
- 일반 대비 가격 60~70%, 속도 70~80% 범위부터 시험
- 가격 기록에서 성공률·노선 다양성 측정

### F124 · 가속 선로 지배 전략

위험: 속도 순위에서 비용 상한까지 가속 선로를 채우는 단일 해답.

보완:

- 맵별 비용 상한이 모든 주요 직선을 가속으로 바꿀 수 없게 설계
- 직접 노선·분기 절약·Combo 가속과 경쟁하도록 배치
- 가속 선로 사용률과 기록 상위 노선 다양성 측정

### F125 · Combo 과잉 보상

위험: 시간·비용보다 Combo만 극대화하는 우회가 점수 최적이 될 수 있다.

보완:

- 점수 비중 `45/45/10 TEST_VALUE`
- 최종 속도 `2× TEST_VALUE` 상한
- 하역 가속 시간 누적 금지
- Combo 2/3/4/5+의 시간 절감·점수 기여를 별도 telemetry로 측정

### F126 · 추천 설계도 정답 누출

위험: 추천 노선이 최적해에 가까우면 설계 탐색이 사라진다.

보완:

- 추천은 안전한 완주 기준만 제공
- 별·랭킹 기준보다 느리거나 비싸게 설계
- 튜토리얼 이후 기본 숨김 또는 명시적 토글
- 추천 노선 사용률과 자체 수정률 측정

### F127 · 일시정지 랭킹 성격

관찰: 일시정지 허용은 실시간 반응보다 계획·실행 정확도를 평가한다.

판정: 의도와 일치. 다만 일시정지 중 모든 조작 금지, 재개 카운트다운, run clock 정지를 동일하게 적용해야 한다.

### F128 · 3별 리더보드 Gate

위험: 사회 비교가 늦게 열려 초반 동기가 약해질 수 있다.

판정: 맵 이해 후 경쟁시키는 숙련 Gate로 타당. 별은 누적 획득, 목표는 사전 공개, 클리어 진행에는 별을 요구하지 않는다.

### F129 · 미학습 기믹 도전

위험: 일일/주간 첫 시도가 설명 비용으로 소비된다.

보완: 한 화면 micro tutorial, 실제 맵 위치 강조, 설명 재열람, 무제한 재도전, 첫 시도 기록 인정.

### F130 · 구조적 완주 검사 범위

위험: 시스템이 LIFO 해답까지 풀면 퍼즐을 대신하고, 너무 약하면 명백히 불가능한 노선으로 출발한다.

보완: graph reachability·영구 trap만 검사. 적재·하역 순서와 시간 해답은 검사하지 않는다.

### F131 · 별 점수 기준 변동

위험: 온라인 참가자 분포 기반 목표면 이미 얻은 별의 의미가 변한다.

보완: 별은 버전 고정된 맵 목표값. 백분위는 기간 도전 보상에만 사용.

### F132 · 건설 비용 수치 조기 고정

판정: 모든 비용·배율·가중치는 `TEST_VALUE`. 최소 3개 수작업 맵과 자동 solver/simulation 또는 human play 전 영구 확정 금지.
