Status: `RESOLVED_FOR_CURRENT_OWNERS · 2026-08-28 KST`

## Incident

`기획서/40_표현/VISUAL_DIRECTION.md` was marked `CURRENT_CANON` while also prescribing historical/unsupported score, stars/ranking, leaderboards, a 1–10 tutorial progression, performance rail attributes, tunnels/bridges, and a required mascot direction. Those claims conflicted with the current finite T1→T6→VS_DEMO_01 slice, SX-DEC-056B block, and actual runtime consumer inventory.

## Solution

- Recorded the user-approved `SX-DEC-061` Board-first Cozy Neo-Arcade lock.
- Made the current lock and its product/rule boundaries the first read surface of `VISUAL_DIRECTION.md`.
- Reclassified the conflicting body as historical notes unless a current owner re-approves a statement.
- Added a structured text owner for the generated planning board so image pictograms cannot become requirements.

## Lesson

A current visual-direction document must not let historical feature/UI examples silently reactivate product systems. Current visual guidance needs an explicit flow owner and an evidence boundary whenever it uses generated planning imagery.

## Base promotion assessment

`NO_BASE_PROMOTION` — the stale feature names and the T1→T6/SX-DEC-060 constraints are project-specific. Base already requires canonical freshness auditing and does not need a project-specific rule copied into shared policy.

## Validation boundary

This correction is documentation-only. It does not prove runtime rendering, Windows/Android behaviour, audio, accessibility, human comprehension, player experience, asset rights, or release readiness.
