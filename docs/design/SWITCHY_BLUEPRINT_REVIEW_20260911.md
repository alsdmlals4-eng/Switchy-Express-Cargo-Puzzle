# Switchy Express 사람용 블루프린트 · 제작 준비 검토본

문서 목적: 사용자가 게임 전체를 읽고 최종 승인할 수 있도록 한다. 최신 위임 기획과 실제 코드·맵에서 파생한다. 원본 규칙과 데이터의 책임은 기존 정본에 있다.
예시 TEN_PACES_HUMAN_BLUEPRINT_20260910_ORGANIZED.pdf는 92쪽의 구성 참고다. 인물·무공·전투·수치·이미지는 전용하지 않는다.
최신 승인: 2026-09-11 블루프린트와 실제 인게임용 이미지 후보 제작 허용. 게임 구현·병합은 최종 승인 이후다.
기획 owner: docs/superpowers/specs/2026-09-10-core-preserved-art-and-experience-replan.md. 기존 PDF는 보존한다.

## 읽는 순서와 승인 범위
방향과 재미 → 상세 SWOT → 시스템과 플로우 → 화면·상태 → 데이터·콘텐츠 → 자산 아틀라스 → 구현 순서와 검수.
‘기존 구현’은 지금 코드에 있는 것, ‘권장 설계’는 승인 후 적용할 것, ‘자산 후보’는 새로 제작했지만 최종 승인 전인 이미지를 뜻한다.
최종 승인 대상은 이 문서의 변경 권장안과 후보 자산이다. 생성 성공이나 PDF 수록만으로 실제 게임 적용·검증을 완료 처리하지 않는다.
노선 규격과 필요한 상태 자산이 준비되지 않으면 전체 구현 준비 완료를 주장하지 않는다. 준비 부족은 마지막 표에 드러낸다.

## 핵심 경험 · 지나치는 것도 설계다
플레이어는 선로뿐 아니라 만날 화물과 실을 순서를 설계한다. 마지막에 실은 화물이 먼저 내려가므로, 가장 가까운 화물을 지금 싣는 것이 항상 좋은 선택은 아니다.
화물 역순 계획 → 선택적 적재 → 역 옆 배송 → 점유 전 분기 → 같은 노선 재도전이 하나의 판단 루프다.
편안한 표현과 생각할 거리는 함께 유지한다. 시간 제한은 존재하므로 타이머 없는 게임으로 소개하지 않는다.
독창성 후보는 ‘철도’가 아니라 무제한 LIFO·건너뛰기·재방문·직접 분기의 결합이다. 유일한 게임이라는 주장은 하지 않는다.

## 전체 플로우맵
메인 → 스테이지 북 → 스테이지 브리핑 → 건설 → 연결 검사 → 운행 → 결과.
건설 검사 실패 → 문제 칸 확인 → 건설 수정. 검사 통과는 성공 보장이 아니라 운행 가능한 구조라는 뜻이다.
운행 ↔ 일시정지. 운행 → 성공 / 시간 종료 / 노선 끝. 결과 → 같은 노선 다시 운행 / 노선 수정 / 스테이지 선택.
|구간|보존|새로 만드는 상태|
|Retry|맵과 노선|화물·시간·분기 실행 상태·시도 식별자|
|Edit|맵과 노선|건설 선택 상태, 실행 효과 초기화|
|다음 스테이지|기존 진행 정책|해당 맵 정의와 새 시도|
정지·결과 패널은 보드 입력을 소비해 뒤의 선로를 잘못 누르지 않게 한다.

## 건설 규칙과 오류 안내
현재 비용과 권장 기준을 표시한다. 권장 비용 초과로 출발을 막거나 실패시키지 않는다. BUILD 철거는 전액 환급이다.
시작점에서 실제 운행 가능한 구성에 필요한 화물과 각 역의 상하좌우 서비스 칸이 포함돼야 한다. 무관한 끊긴 선로 섬은 출발을 막지 않는다.
|상태|표시|조작|
|배치 가능|얇은 테두리·낮은 불투명도|현재 도구 배치|
|배치 불가|금지 기호+이유|규칙 상태 변경 없음|
|연결 문제|실제 문제 칸과 메시지|회전·철거·재배치|
|검사 통과|출발 버튼 활성|운행 시도 생성|
허용하지 않은 새 Undo·드래그 칠하기·자동 해법 기능을 있는 것처럼 표시하지 않는다.

## 화물과 하역 · 정확한 순서
마지막에 실은 화물이 TOP이다. 같은 종류가 TOP부터 연속으로 쌓여 있을 때만 함께 내린다. 용량 상한과 임의 재정렬은 없다.
예: 아래 빨강 / 파랑 / 파랑 TOP → 파랑 역에서 파랑 둘 하역 → 빨강 노출. 빨강 역은 위 파랑을 건너뛰지 못한다.
같은 칸에서 화물 접촉과 역 서비스가 겹치면 현재 코드에서는 적재가 먼저, 하역 판단이 다음이다. 새 TOP을 기준으로 역 일치를 검사한다.
|종류|표시|목적지|
|RED_STAR|빨강 · 별|빨강 역|
|BLUE_DIAMOND|파랑 · 다이아|파랑 역|
|YELLOW_TRIANGLE|노랑 · 삼각|노랑 역|
|WASTE_CRATE|폐기물 · 상자|처리장|
HUD는 모르는 종류를 파랑으로 대체하지 않는다. 색·도형·문구를 동시에 사용한다.

## 역 · 선로 위가 아닌 옆에서
열차와 역의 칸 좌표 차이 절댓값 합이 정확히 1일 때 서비스한다. 상·하·좌·우 한 칸만 인정한다. 대각선·거리 2·역 자체는 제외한다.
역 밑에 선로를 깔도록 보이는 이미지를 피하고, 서비스 칸은 선로와 다른 선 패턴으로 나타낸다.
일반 역은 자신의 화물 종류만 내린다. 처리장은 폐기물을 받는다. 역 서비스 소유권이 겹치는 잘못된 맵은 임의 우선순위를 만들지 않고 거부한다.
승인 후 검증: 네 방향 성공 / 대각선 실패 / 역 자체 배치 금지 / 잘못된 TOP 무하역 / 겹친 서비스 거부.

## 감속과 폐기물 · 추가가 아닌 기존 선택의 깊이
황색 주의 구간은 실제 맵과 속도 로직에 따라 감속한다. 파랑 회복 연출은 정상 속도로 돌아가는 표시이며 BOOST가 아니다.
폐기물은 적재 순서와 처리장 방문을 요구한다. 일반 배송 뒤에 회수하는 전략은 유용할 수 있지만 자유 건설의 다른 해법을 실패로 바꾸지 않는다.
|요소|예고|사건|검증|
|주의 구간|황색+주의 패턴|진입 감속·이탈 복귀|맵 칸과 실제 속도 일치|
|폐기물|상자형 고유 기호|적재·TOP 방해·처리장 하역|일반 역에서는 내리지 않음|
|장식|비상호작용 재질·낮은 강조|규칙 사건 없음|화물·위험으로 오인하지 않기|
무작위 생성·추가 속도 변화·새 함정 종류는 이번 구현 범위에 넣지 않는다.

## 화면 명세 · 메인·선택·브리핑
메인은 기존 게임 제목 정체성을 유지한다. 선택된 청회색 보드와 승인된 제목 이미지를 재사용할 수 있지만, 미채택 야간 메인 배경을 몰래 적용하지 않는다.
스테이지 북은 이름·기존 진행 상태·해당 판단을 보여준다. 없는 이어하기나 미구현 RB13~18을 플레이 가능한 버튼으로 노출하지 않는다.
브리핑은 목표 → 관련 규칙 하나 → 조작 → 건설 시작 순서다. 모든 해결 순서를 설명하는 답안지가 아니다.
|화면|첫 포커스|복귀|금지|
|메인|주 행동|기존 종료 정책|새 저장 기능 암시|
|북·스테이지|현재 선택|상위 화면|미구현 콘텐츠 노출|
|브리핑|건설 시작|선택 화면|정답 노선 자동 공개|

## 화면 명세 · BUILD와 RUN
BUILD: 상단 목표·비용 / 중앙 보드 / 우측 도구와 문제 이유 / 하단 출발. RUN: 상단 시간·진행 / 중앙 열차·경로 / 우측 TOP 묶음·나머지 적재물 / 하단 수동·자동·정지.
TOP과 연속 동일 그룹을 우선한다. 위쪽부터 표시하더라도 실제 저장 순서인 아래→위 배열은 변경하지 않는다.
긴 목록은 표시 그룹을 제한하고 정확한 초과 개수와 스크롤로 나머지를 제공한다. 표시 제한은 화물 용량 제한이 아니다.
1920×1080 논리 화면과 1280×720 창을 구분한다. 작은 화면에서 보드와 조작 영역이 겹치면 하단 축약 목록을 사용하되 선로를 가로세로 다르게 늘리지 않는다.

## 결과와 복구 · 실패를 다음 판단으로
|결과|보여줄 사실|다음 행동|
|성공|실제 배송 완료·시간·비용|다음 스테이지 / 재운행 / 수정|
|시간 종료|미배송이 남은 실제 종료 이유|적재·방문 순서 검토|
|노선 끝|진행할 연결 경로가 없는 사실|분기·종착 연결 검토|
같은 사건을 화면이 다시 계산하지 않는다. 판정의 우선순위는 운행 제어의 결과를 따른다.
큰 성공 효과가 결과 문구를 덮지 않게 한다. 효과 직후와 종료 후 안정 화면을 모두 검사한다. 재시도 때 이전 화물 비행·선택 강조·사운드 예약이 남으면 안 된다.

## 자산 제작 계약 · 그림에서 실제 소비까지
새 비트맵은 이미지 모델에서 제작하고 원본·해시·크기·알파·후보 상태를 기록한다. Aseprite는 필요한 프레임 정렬·검사·내보내기에 사용하며 그림 대신 절차 도형으로 대체하지 않는다.
|가족|소비처|완료 조건|
|보드|ProductBoardRenderer terrain|승인된 바탕, 따뜻한 veil과 색보정 분리|
|선로|straight/curve/crossing/switch|공유 포트·폭·접선·회전과 조립 검증|
|열차·역·화물|renderer texture slots|동일 시점·크기·접지점·모든 종류|
|UI|기존 Control 화면|이미지에 문구를 굽지 않음, 상태별 명확한 차이|
|모션|실제 사건 consumer|기준 피벗·프레임·시간·정지·취소|
수록된 시트와 실제 슬라이스 가능한 아틀라스는 구분한다. 좌표·패딩·피벗이 없는 시트를 완성 아틀라스라 부르지 않는다.

## 모션과 피드백 데이터
|대상|권장 표현 시간|정지·취소|규칙 경계|
|배치·분기 수락|120~160ms|새 상태로 교체|노선은 controller가 확정|
|화물 적재·하역|180~240ms|Pause 고정 / Retry 취소|사건 확정 뒤 표시|
|감속·복귀|240~320ms|현재 속도 상태로 수렴|속도 값 변경 안 함|
|감소 모션|이동·확대 대신 정적·불투명도|동일 상태 전달|정보 손실 없음|
기존 파랑 적재: 4프레임, 각 60ms, 448×448, stride 450, 총 240ms. 이는 해당 준비본의 규격이며 새 종류로 자동 전이되는 검증은 아니다.
소리 없이도 필수 정보가 전달돼야 한다. 반복 사건이 무한 대기열이나 중복 보상을 만들지 않는다.

## 데이터 표 · 맵과 표시 모델
|원본|핵심 필드|검증|
|FiniteMapDefinition v3|map_id, board_size, start_cell, station_placements, cargo_placements|ID·좌표·종류·서비스 겹침|
|지형|blocked_cells, caution_track_cells, board_decorations|장식과 통행 금지의 역할 구분|
|건설 표시|current_cost, recommended_cost, start_enabled, primary_reason|권장 비용을 상한으로 해석하지 않음|
|적재 표시|cargo_type, index, top, stack_size|모든 종류·TOP·연속 그룹 일치|
|실행 상태|phase, route_controls, time_remaining|정지·잠금·결과와 동일|
운행 remaining_map_cargo의 0 기본값을 사실로 표시하지 않는다. 실제 지상 화물+적재 미배송 수량에서 읽기 전용으로 만든다.

|순서|작업|완료 증거|
|1|정본·현재 main·PR 재확인, 승인 범위 고정|정확한 SHA와 승인 자산 manifest|

구현 보류는 최종 승인으로만 해제한다. 별도 PR과 미확인 사용자 변경은 흡수하지 않는다.

## 검수표 · 자동 검증과 최종 사용자 승인
모든 화물 표시 / TOP 묶음 / 무제한 스택 / 4방향 서비스 / 대각선 거부 / 무관한 선로 섬 / 점유 잠금 / 적재 취소 / Pause·Resume / Retry·Edit / 세 결과를 검사한다.
선로 직선·곡선·S·T·교차·4회전과 작은 화면을 검사한다. 새 이미지가 실제 경로에서 로드되고 투명 여백이 클릭·겹침을 망치지 않는지 확인한다.
머신 검증은 필수, 5인 이해도·플레이 경험 연구는 요구하지 않는다. 재미·가독성의 최종 사용자 판단과 출시·권리 검증은 별도다.
자산 후보·정본 등록·구현·머신 검증·실행 촬영·사용자 승인을 한 칸으로 합치지 않는다.
